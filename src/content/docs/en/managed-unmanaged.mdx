Every C2Go record, pointer declaration, and function boundary can carry a **managed** or **unmanaged** world. This is a compiler-checked memory contract, not just documentation.

## Unmanaged is the default

The current translation-unit default is fully unmanaged (`managed(0)`). A plain declared-only function is treated as an unmanaged host import. A function definition is internal C2Go code regardless of that declaration default.

Managed records and pointers are opt-in. Place the public `managed` macro after the `struct` or `union` keyword so the attribute applies to the type declaration:

```c
#include <c2go.h>

struct managed Node {
    struct Node *next;
    int value;
};
```

Managed pointers refer to memory tracked with precise Go GC metadata. Their stores receive the write barriers required by the runtime. The marker does **not** make a stack local safe to retain after its frame ends.

## Unmanaged is outside precise pointer tracking

Unmanaged pointers are raw values similar to `unsafe.Pointer`. They are used where precise GC ownership and layout cannot be proven and at external C ABI boundaries. A value in Go-visible stack or object storage is still conservatively scanned and kept alive, but it does not carry the precise managed-AS1 write-barrier contract.

```c
struct unmanaged RawBuffer {
    void *data;
    long length;
};
```

Ordinary `malloc`, `calloc`, `realloc`, and `free` retain manually released, unmanaged C semantics; the compiler does not rewrite them into typed `gc_malloc`. The current c2go-libc implementation uses Go `[]byte` backing storage and an internal registry to keep each block alive until `free`. The payload is not scanned for managed pointers, so it is neither a substitute for typed managed allocation nor the host system allocator.

## Set a region default

Use pragmas when adapting a group of declarations. The managed form requires a numeric bitmask: function declarations = `1`, pointers = `2`, records = `4`.

```c
#pragma c2go managed(7) push
struct Node { struct Node *next; int value; };
int package_internal(int); // declaration is an internal C2Go reference
#pragma c2go pop
```

The parser requires the literal integer—`managed(C2GO_FUNC | C2GO_PTR)` is not accepted. An unmanaged region is the `0` shorthand:

```c
#pragma c2go unmanaged push
struct NativeHeader { void *handle; long flags; };
extern int native_open(struct NativeHeader *);
#pragma c2go unmanaged pop
```

Prefer the narrowest practical region. A broad managed region makes lifetime assumptions hard to review; a broad unmanaged region makes loss of GC precision easy to miss.

## Warnings for lossy conversions

Some crossings remain representable but lose precise tracking. The compiler warns when you:

- pass, store, or return a managed pointer in unmanaged form;
- convert a managed pointer to an integer.

These lossy address-space warnings are in `-Wc2go-managed-as1`. During migration you can inspect them as warnings; for maintained code, prefer:

```sh
-Werror=c2go-managed-as1
```

Disabling the warning does not make the conversion precise.

Stack-address retention has a separate default-on warning, `-Wc2go-managed-stack-escape`. It only catches direct source patterns; use `-Werror=c2go-managed-stack-escape` **and** the standalone [whole-program stack escape audit](/en/docs/stack-escape-audit/).

## Errors for unsound layouts

C2Go rejects operations that would make the GC's view structurally wrong:

- bit-casting between managed pointer types with incompatible GC layouts;
- putting a managed field inside an unmanaged record;
- using packed or per-field alignment overrides on managed records; and
- ambiguous overlapping pointer fields in a managed union representation.

Do not work around these errors with integer casts. Redesign the boundary: keep native storage unmanaged, or copy data into a managed representation with an explicit lifetime.

## Boundary rule of thumb

Use managed heap allocation for data that lives with Go objects or survives across Go calls. Do not confuse a managed type with automatic escape promotion: never retain the address of a C stack local. Use unmanaged memory when a native API owns the allocation or requires a native pointer representation, and make every crossing visible in declarations.
